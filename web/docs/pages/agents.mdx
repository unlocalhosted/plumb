Coding agents write a lot of styles, and they'll happily invent `p-[13px]` when nothing tells them otherwise. Plumber gives an agent your tokens with their reasons before it writes, checks its edits after, and tells it exactly what to change, or to stop and ask you.

## Set it up

```sh
npx plumber install --agent claude
```

For Claude Code that writes two things, keeping anything already in your settings:

- **`.claude/skills/plumber/SKILL.md`**: how to use Plumber, written for agents.
- **A hook in `.claude/settings.json`** that runs Plumber after every edit:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [{ "type": "command", "command": "plumber check --changed --agent --strict-ledger" }]
      }
    ]
  }
}
```

Other agents get instructions in the place they read them:

| Agent | `--agent` | Writes | Hook after edits |
| --- | --- | --- | --- |
| Claude Code | `claude` | `.claude/skills/plumber/SKILL.md` | yes |
| Cursor | `cursor` | `.cursor/rules/plumber.mdc` | yes |
| Codex, and any other | `codex`, `generic` | a block in `AGENTS.md` | no |
| Copilot | `copilot` | a block in `.github/copilot-instructions.md` | no |
| Gemini CLI | `gemini` | a block in `GEMINI.md` | no |
| Windsurf | `windsurf` | `.windsurf/rules/plumber.md` | no |

Pass `--agent` more than once to set up several. `npx plumber install --list` shows what it would write without writing it.

## The loop

1. **Before writing styles**, the agent looks up your tokens instead of guessing (`npx plumber decisions --family spacing`), and can try a snippet without touching a file:

   ```sh
   echo '<div className="gap-10 text-gray-500" />' | npx plumber try --agent
   ```

2. **After each edit**, `plumber check --changed --agent` lists only new problems in the files it changed, each as one instruction. It repeats until the output is `0 new`.

Here's that output for a 13px gap:

```text
1 new
## 1 of 1  gap 13px isn't on your spacing scale
Rule: provenance/spacing
Why: Off-scale spacing makes layouts drift apart and can't be changed from the theme.
Tokens:
- 8px: use gap: var(--spacing-related); why: Related items use eight pixels.
- 16px: use gap: var(--spacing-group); why: (no reason recorded)
Sites: src/new.css:1:8
- src/new.css:1:8  `gap: 13px`
  Compiles to: gap: 13px (via stylesheet)
  Choose a token using its reason, then edit at src/new.css:1:8:
    replace `gap: 13px` with `gap: var(--spacing-related)`  (8px)
    replace `gap: 13px` with `gap: var(--spacing-group)`  (16px)
```

Each site ends in one of four instructions:

| Instruction | Means |
| --- | --- |
| **Edit** | one token fits: make exactly that edit |
| **Choose a token using its reason** | several fit: pick by the reasons and what the element is for |
| **NEEDS-DECISION** | nothing fits: stop and tell you the sites and the value it wanted |
| **Fix** | a habit or other finding: follow the instruction |

This is where your `why:` comments pay off: they're what the agent chooses by.

## What an agent must never do

The skill and every `--agent` output say the same thing:

- Never edit the config, the ledger or the theme to make a finding pass. A new token or an exception is your decision.
- Never run `plumber accept`, `accept-decisions` or `baseline` unless you ask. If something should be an exception, it gives you the `plumber accept … --why` line to run.
- Never invent a nearby value, like `p-[13px]` or `p-3.25`, to get around a finding.

The hook adds `--strict-ledger`, so if an agent does change the ledger, the check fails.
