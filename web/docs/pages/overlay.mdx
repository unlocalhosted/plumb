The overlay is Plumber in your browser. Hold Alt over any element of your running app to see its reading: the JSX that made it, each value that's off your scale, and the tokens that fit. Pick one and Plumber writes it to your source.

It runs only in development. Production builds carry none of it.

## Wire it in

`plumber install --overlay` looks at your project and prints the wiring. Add `--write` to make the change and see the diff.

```sh
npx plumber install --overlay
npx plumber install --overlay --write
```

### Vite

One plugin, listed **before** `react()`, so it can mark each JSX tag with where it was written before React compiles it:

```ts
// vite.config.ts
import { plumb } from '@unlocalhosted/react-plumber/vite'
import react from '@vitejs/plugin-react'

export default { plugins: [plumb(), react()] }
```

The plugin applies only to `vite dev`. It adds Plumber's routes to your dev server and its script to the page; your source files are never changed by this.

### Next.js (App Router)

Three pieces: a config wrapper, a route that serves the overlay, and a component in your root layout.

```ts
// next.config.mjs
import { withPlumb } from '@unlocalhosted/react-plumber/next/config'
export default withPlumb(nextConfig)
```

```ts
// app/%5F_plumb/[...path]/route.plumb.ts
import { createPlumbRoute } from '@unlocalhosted/react-plumber/next'
export const runtime = 'nodejs'
export const { GET, POST } = createPlumbRoute()
```

```tsx
// app/layout.tsx, inside <body>
import { PlumbOverlay } from '@unlocalhosted/react-plumber/next'

<PlumbOverlay />
```

The folder is `%5F_plumb`, not `__plumb`, because Next.js treats folders starting with `_` as private. In production the wrapper changes nothing, the route answers 404 and the component renders nothing.

### Anything else

Run Plumber's own server beside your dev server, then add its script to your development page:

```sh
npx plumber serve --overlay --port 7331 --origin http://localhost:5555
```

Run `npx plumber install --overlay` again while it's running to print the exact script tag, with the token it needs.

## Use it

| Gesture | What happens |
| --- | --- |
| Hold **Alt** (Option on a Mac) and hover | The element under the pointer is outlined, with its component and how many values are off. |
| **Click** while holding Alt | Pins its reading. |
| **Alt+↑ / Alt+↓** | Steps from the element's JSX to the components above it. |
| **Esc** | Closes the reading. |

The reading shows where the element was written, a drawing of its box with each measured value, and every finding on it with its ledger status. For each off-scale value it offers the tokens either side with your reasons.

Picking a token **previews** it on the page. Nothing is saved until you press **Write**. **Before** shows the source version again, and **Undo** lifts every preview. **Copy for agent** puts the reading on your clipboard for an agent to act on.

### Blueprint mode

Press **Alt+B** and the whole view becomes its own blueprint: a wireframe of the running page, with every drift in view drawn where it lives. Words become bars, so structure and rhythm read without copy. Gaps on your scale are faint dimensions named by their token. Anything off the scale is an amber break on its own geometry: an arc on a corner, a bracket across a gap or padding, a bracket beside text, a dot for a colour or shadow. Beside each numeric break, the nearest token is ghosted in mint at its own size, so 14 reads against 12 in place. Each element carries one badge with its count, and a red wash says how far it sits from the system. Rails along the left and top edges carry every gap in view as a tick named by its token, so a glance down the margin says whether the page keeps one rhythm. Nothing else is lettered at rest.

| Gesture | What happens |
| --- | --- |
| **Alt+B** | Blueprint on or off. **Esc** also leaves. |
| **Point** at a break, or **Tab** to it | One note in words: what is off, the nearest tokens, what a click does. |
| **Click** a break, or **Enter** | Opens its chooser. Pointing at a step previews it; clicking picks it. Several picks go in one **Write**. |
| **Hold D** | The view as designed: every drift takes its nearest token at once and the ink turns mint. Release puts it back. |
| **L** | The punch list: every drift in view in rows. |
| **N / P** or **] / [** | The next or previous drift in view. |

The title block in the corner names the sheet: the route, the viewport and its breakpoint, the tally of what is on the system and what is off, and the causes of the drift by count. The first cause is the decision that closes the most; pointing at one outlines every element it touches. Leaving puts the page back exactly as it was.

### Editing text

Double-click a label in a reading, or press **E**, to edit its words in place. Write saves them to the JSX or the string literal they came from, keeping its quotes. Text that comes from a prop, an expression or a translation isn't editable here, because it isn't written in that place; edit it where it is.

## What it won't write

The overlay writes only an exact replacement it can prove, and says why when it can't:

- **No choice made**: two tokens fit and you haven't picked one, or no token is close enough. Use Copy for agent, or edit by hand.
- **The file changed** since Plumber read it. Read it again and retry.
- **Not your source**: config files, `.plumber/`, symbolic links and anything outside the project are never written.
- **Not static**: a class built at runtime, or text from an expression.

Every edit is worked out again on the server from the current file, so the page can never ask Plumber to write something else.

<Callout kind="note" title="Who can write">
On Vite, Plumber answers only to the page your dev server serves, on your own machine. Next.js and `plumber serve` add a token that only your development page has.
</Callout>
