React Plumber finds where a React app on Tailwind v4 or plain CSS drifts from its design system, and lets you fix it in the browser. You need Node 22.18 or newer.

## 1. See what is off

```sh
npm install -D @unlocalhosted/react-plumber
npx plumber check
```

`check` reports the values that aren't on your tokens, along with broken styles and gaps in your setup. Before you set Plumber up it exits 0 and doesn't edit your code. It does write a cache to `.plumber/`.

`npx plumber` on its own prints a few lines about your project and the next step.

## 2. Choose your rules

```sh
npx plumber init
```

In a terminal, `init` asks about your spacing, colours, text and border radius, one question at a time. `--yes` takes every suggested answer. It writes `plumber.config.ts`, turns on four habits and records today’s findings as the **baseline** in `.plumber/ledger.jsonl`. After that, `npx plumber check` fails only on new errors.

<Callout kind="careful">
`init` writes to your repo, and your answers can add tokens to your theme. Commit your work before you run it. If a config already exists it stops, unless you pass `--force` to replace it.
</Callout>

## 3. Put it on your page

```sh
npx plumber install --overlay           # print the setup for Vite or Next.js
npx plumber install --overlay --write   # make the change and show the diff
```

For Vite, the overlay is one plugin, listed **before** `react()`:

```ts
import { plumb } from '@unlocalhosted/react-plumber/vite'
import react from '@vitejs/plugin-react'

export default { plugins: [plumb(), react()] }
```

Start your dev server as usual, then:

| Gesture | What happens |
| --- | --- |
| Hold **Alt** (Option on a Mac) | Shows what the element under the pointer is made of, and what is off. |
| **Alt + click** | Opens that element’s editor and its notes. |
| **Double-click** words | Edits them in place. **Enter** writes them to your source. |
| **Alt + B** | Turns Blueprint on, to fix what is off across the page. |
| **?** | Lists every shortcut. |

<Callout kind="why" title="How Plumber finds the line">
In development, `plumb()` adds the file, line and column to each DOM tag in the code your dev server serves. Your files aren’t changed by this, and production builds don’t get the attribute. Before a write, Plumber checks that position against the file on disk. If it can’t confirm it, it tells you why and doesn’t write.
</Callout>

## 4. Check pull requests

```sh
npx plumber install --ci
```

This adds a GitHub Action that judges each pull request against the baseline, so you can turn it on before the old drift is fixed. Set [who can approve ledger changes](/docs/ci) before your first new token or exception.

`npx plumber doctor` shows which of these steps are done and the command for each one that isn’t.
