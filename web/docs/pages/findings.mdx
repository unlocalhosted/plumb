A finding says what was written, what is wrong with it, where it is and what to use instead. The reason is printed once per rule, under **Why**, at the end of the report.

```text
  !  gap: 13px                               off your spacing scale      index.css:10
     → var(--spacing-related) (8px) · var(--spacing-group) (16px)

Why
  Off-scale spacing makes layouts drift apart and can't be changed from the theme.
```

## Severity

| Severity | Means | Fails `plumber check` |
| --- | --- | --- |
| `error` | drift, or a style that can't work | yes, exit 1 |
| `warn` | worth a look, such as a literal that equals a token | no |
| `info` | a note, such as a value Plumber couldn't read | no |

With no config and no ledger, `plumber check` exits 0 whatever it finds. Once you have either, new errors fail the check. A problem with the command itself, such as a bad flag, exits 2.

## Findings with several sites

The same drift in several places is one finding: the same rule, family and amount, with every site listed. The default report shortens long lists. `--all` shows the full report, and `--json` lists every site.

Findings that the [ledger](/docs/the-ledger) fully covers show as one summary line. `--debt` lists the debt, and `--all --verbose` lists every known finding.

## Status

Every site carries a status from the ledger:

- **new**: not in the ledger. New errors fail a check.
- **debt**: drift you already had when you adopted Plumber, recorded so that it doesn't block you.
- **exception**: accepted on purpose, with the reason someone gave.

A finding is new if any of its sites is new.

## In JSON

`plumber check --json` prints the same findings as data. Each has its `rule`, `family` and `severity`; the parts above as `title`, `because`, `choices` and `accept`; every site in `sites`, with its status; and `edits`, the exact replacements Plumber would make, which the overlay and agents use. The [report format](/docs/report-format) lists every field.
