## 1. Collect: authored source, not browser layout

- `projectSourceFiles()` uses configured `source` globs, otherwise `src/**/*.{tsx,jsx,ts,js,css}` and `app/**/*.{tsx,jsx,ts,js,css}`; generated/build/package directories are ignored. `analyze()` sends JS/TS/JSX/TSX files to `collectClasses()`. Sources: `src/project.ts:13-19`, `src/project.ts:96-98`, `src/index.ts:86-94`.
- `collectClasses()` reads JSX `className` and `class`, string literals, static template portions, conditional/logical branches, arrays and object keys. Branches supply conditions rather than a simulated runtime result. Sources: `src/collect/classes.ts:220-299`, `src/collect/classes.ts:414-427`.
- `cn`, `clsx`, `cx`, `classNames`, `twMerge`, `twJoin`, `cva` and `tv` are recognized helpers; `cva` treats its first argument as classes and later arguments as recipe configuration. Configuration traversal reads class-bearing recipe keys and variant/compound-variant classes; it does not interpret every recipe string as a class. Custom helpers can extend the registry. Sources: `src/collect/class-helpers.ts:14-32`, `src/collect/classes.ts:273-298`, `src/collect/classes.ts:302-319`.
- Static tracing goes beyond direct literals: `ComputedClasses` follows class-bearing bindings/imports and function returns, helper aliases, arrays, `join(' ')`, `filter(Boolean)` and statically available arguments. “Plumb cannot read any computed class” is **not supported**. Sources: `src/collect/computed.ts:196-266`, `src/collect/computed.ts:278-307`, `src/collect/classes.ts:445-464`.
- General runtime execution is **not supported**: tracing has a 20,000-operation budget and depth 16 limit; function-call tracing has a depth limit. A template class containing a glued runtime hole is retained as an opaque class instead of treating its prefix/suffix as complete classes. Sources: `src/collect/computed.ts:43-46`, `src/collect/computed.ts:254-266`, `src/collect/classes.ts:234-259`.
- A direct class's location comes from the literal/token's source offset, including decoded literal offsets; `sourceSite()` uses line starts to return **one-based line and column**, plus an enclosing anchor. These are source locations, not React/browser source maps. Sources: `src/collect/classes.ts:228-231`, `src/collect/source.ts:36-52`, `src/collect/computed.ts:201-204`.
- `collectStylesheets()` reads the configured/discovered Tailwind entry, recursive CSS `@import`/`@reference`, CSS imports from the JS module graph, and CSS files in source globs. Inline JSX `<style>` contents also enter stylesheet lowering. Sources: `src/index.ts:102-113`, `src/collect/stylesheets.ts:115-142`, `src/collect/inline.ts:163-197`, `src/lower/stylesheets.ts:318-327`.
- `collectInline()` reads `style={{ ... }}` literals and a one-hop const/imported object. It converts camelCase properties to CSS names; numeric nonzero dimensional values get `px`, except custom properties and React's unitless-property list. Thus authored `gap: 13` produces report declaration `gap: 13px`; zero stays `0`. Sources: `src/collect/inline.ts:9-10`, `src/collect/inline.ts:23-36`, `src/collect/inline.ts:83-119`.
- Nonliteral inline property values become `opaque: 'dynamic-value'`; spreads/unknown keys become opaque spread declarations. They are not evaluated as live styles. Sources: `src/collect/inline.ts:98-119`.

## 2. Compile: ask the project's Tailwind

- `lowerTailwind()` resolves Tailwind from the entry's directory, requires v4, and loads that entry with `__unstable__loadDesignSystem`. It uses `@tailwindcss/node` only when that wrapper resolves the same Tailwind installation; otherwise it supplies stylesheet/module loaders to the direct compiler. Sources: `src/lower/tailwind.ts:91-94`, `src/lower/tailwind.ts:120-151`.
- Distinct nonopaque class tokens go through `system.candidatesToCss()`; the returned CSS is parsed by `lowerCss()` into property/value declarations with selector/pseudo/media/etc. conditions. Compiler-owned `--tw-*` assignments are folded where possible, with unresolved assignments retained. Sources: `src/index.ts:99-100`, `src/lower/tailwind.ts:155-162`, `src/lower/tailwind.ts:187-197`, `src/lower/css.ts:109-161`.
- Value-bearing compiling candidates get `authoredValue: true`; value-free utilities and the named values `full`, `none`, `px` do not. Named theme keys selected by the compiler can survive as `decisionRefs` even when `@theme inline` erased their variable names. Sources: `src/lower/tailwind.ts:192-223`.
- `analyze()` attaches each class's actual source site, owner, refs and origin to the compiled declarations. Bracket-value class syntax gets origin `arbitrary`; other classes get origin `class`. Sources: `src/index.ts:129-141`.
- `lowerStylesheets()` compiles Tailwind-bearing CSS with the project's `compile()`/`build([])` API. Independent stylesheets receive an appended `@reference` to the project entry when needed. The source map returns declarations to original CSS source positions; an `@apply` declaration points to the authored `@apply` statement and gets origin `apply`. Sources: `src/lower/stylesheets.ts:148-186`, `src/lower/stylesheets.ts:225-242`.
- Applied utility tokens also go through `lowerTailwind()` to recover `authoredValue` and selected decision references. This is why `@apply gap-[13px]` is judged as an authored spacing value even though its origin is `apply`, not `arbitrary`. Sources: `src/lower/stylesheets.ts:338-355`, `src/rules/families.ts:24-27`.
- Plain CSS without Tailwind features can be parsed directly, retaining declarations and import conditions. In this fixture the plain `gap: 13px` shares the Tailwind-bearing entry, so it goes through the stylesheet compiler alongside `@apply`. Sources: `src/lower/stylesheets.ts:279-316`, `fixtures/docs-judged/src/styles.css:1-20`.
- Inline styles bypass Tailwind entirely and enter the combined declaration list from the collector. Claiming that **all five forms compile through Tailwind is not supported**. Sources: `src/index.ts:140-142`, `src/collect/inline.ts:98-119`.

## 3. Resolve: a static comparison, not the cascade

- `readDecisions()` builds a variable context from CSS metadata and compiler theme entries; it resolves decision values and removes `resolved` for dynamic/unresolvable tokens. Conditional or differing backing definitions cannot safely become one light-mode value. Sources: `src/decisions/index.ts:41-51`, `src/decisions/index.ts:104-134`.
- `resolutionContext()` additionally scopes emitted `--tw-*` variables by source file, owner and conditions. `familyProvenance()` calls the resolver and writes `declaration.resolved` only when successful. Sources: `src/rules/provenance.ts:46-61`, `src/rules/provenance.ts:89-100`, `src/rules/provenance.ts:203-208`.
- `resolveValue()` recursively substitutes balanced `var()` calls, including nested fallbacks; missing variables without a usable fallback, cycles, dynamic variables, excessive recursion, unbalanced syntax, `env()` and `light-dark()` remain unresolved. Sources: `src/decisions/resolve.ts:72-98`.
- It folds supported `calc()` arithmetic using multiplication/division and addition/subtraction, rejecting incompatible dimensions, unit-bearing divisors and division by zero. Different absolute units can be added after conversion to px; different relative units cannot. Sources: `src/decisions/resolve.ts:33-69`, `src/decisions/resolve.ts:100-109`.
- **`resolved` is not always a px string.** `resolveValue()` retains the resulting unit; `pixels()` supplies comparison numbers separately. `pixels()` supports absolute length units and assumes **1rem = 16px**, independently of the actual computed root font size. Nonzero `em`, viewport units, percentages and nonzero unitless lengths have no pixel comparison. Zero of any parsed unit compares as zero. Sources: `src/decisions/resolve.ts:4-11`, `src/decisions/resolve.ts:69`, `src/decisions/resolve.ts:109`, `src/rules/provenance.ts:117-126`.
- A resolver-returned string is not proof of computability: unsupported non-`calc` functions can remain as strings because the resolver returns its output unchanged after substitutions. For spacing, `pixels()` then cannot compare them. A general browser-equivalent `min()`/`max()`/`clamp()` evaluator is **not supported**. Sources: `src/decisions/resolve.ts:98-109`, `src/decisions/resolve.ts:5-11`, `src/rules/provenance.ts:117-121`.

## 4. Match: family policy and actionable choices

- `familiesFor()` selects families by CSS property; `gap` belongs to spacing. Judged families are spacing, color, radius, type, motion, elevation and z. Size/opacity exist in decision inventory but are **not supported as provenance-judged families**. Framework stylesheet declarations, keyframes and compiler-owned class/apply declarations without `authoredValue` are excluded. Sources: `src/rules/families.ts:7-27`, `src/report.ts:9`.
- Default identity is **value** for spacing, radius, and type properties other than `font-family`; **reference** for color, motion, elevation, z and `font-family`. Each family's configured `identity` can override it. Default allowed origin is project. Sources: `src/rules/provenance.ts:109-115`.
- References are checked before value equivalence. A recognized decision reference passes when its origin/tier is allowed, even if its actual value is dynamic. Disallowed origin/tier produces framework/tier findings. Compiler-selected `decisionRefs` participate in attribution, protecting named tokens erased by inline compilation. Sources: `src/rules/provenance.ts:65-84`, `src/rules/provenance.ts:199-226`, `src/rules/attribution.ts:114-118`.
- Default caller policy disallows a primitive when it has an intent-bearing semantic alias; otherwise primitives are allowed. Explicit `callers` overrides this. Sources: `src/decisions/callers.ts:4-29`.
- Value matching uses allowed-origin, resolved, suggestible decisions; `suggest` therefore filters both value matching and suggestions, not only display. Candidates sort primitive before semantic, project before other origins, then name. Equal amounts collapse, preferring a class-actionable token if the earlier equal token has no utility. Sources: `src/rules/provenance.ts:128-159`, `src/config.ts:23-24`.
- Spacing compares px numbers and uses the **absolute authored amount** for negative lengths; numeric equivalence tolerance is `< 1e-6`. Radius/type lengths compare pixels where possible; motion converts s/ms to milliseconds; other comparable values use normalized lowercase strings. Colors compare OKLab distance `< 1e-5` plus alpha difference `< 1e-5`. Sources: `src/rules/provenance.ts:117-126`.
- Spacing “nearest” means the nearest allowed step **below**, then the nearest **above**, not two globally nearest distances. Each must be within `max(4px, abs(value) * 0.5)`; zero, one or two choices can remain. For 13px on this ladder: **12px, then 16px**. Sources: `src/rules/provenance.ts:165-191`, `site/src/docs/recordings/judged.json:221-262`.
- With an active Tailwind numeric scale, choices instead use floor/ceil half steps of `abs(px) / unitPx`, deduplicated. Other numeric families select at most two closest candidates within `max(base, abs(value)*0.5)`, where base is 10 for motion, 1 for z, otherwise 4. Colors select at most two within OKLab distance 0.15, nearest first and name as tie-breaker; alpha participates in equality but not this distance. Unsupported nonnumeric comparisons can have no nearest choices. Sources: `src/rules/provenance.ts:165-191`, `src/rules/families.ts:156`.
- Alternatives are filtered again for origins, caller policy, suggestibility and avoiding self-referential variable fixes. Tier repairs can enumerate aliases without the usual two-choice limit; “every finding has exactly two choices” is **not supported**. Sources: `src/rules/provenance.ts:221-224`, `src/rules/provenance.ts:258-260`, `src/rules/provenance.ts:278-281`.
- Choice `name`, `value`, `resolved`, `why`, `source` and `use` come from decision records. CSS `/* why: */` immediately preceding a token supplies its reason; records may also come from presets, configured functions or DTCG. Shared reasons across more than three distinct tokens become `groupWhy`; token reasons are sentence-selected/truncated. The recorder copies these fields without making up reasons. Sources: `src/decisions/css.ts:48-51`, `src/decisions/css.ts:82-88`, `src/decisions/index.ts:65`, `src/decisions/index.ts:92-103`, `src/decisions/index.ts:152-153`, `src/messages.ts:58-73`, `scripts/docs/record-judged.mjs:66`.
- `useFor()` supplies replacement classes/CSS; finding explanations come from rule templates, not token comments. `makeFinding()` maps `because` to `why` and choices/action to `fix`. Sources: `src/rules/provenance.ts:20-42`, `src/rules/provenance.ts:209-269`, `src/messages.ts:4-20`.

## 6. Surprises worth stating precisely

- Tailwind can compile a numeric spacing utility even when Plumb rejects its amount. `numericSpacing()` treats the numeric scale as replaced when the project resets the spacing namespace or supplies even **one** distinct positive primitive spacing step ≤64px outside layout-role names. The old “needs three custom steps” claim is **not supported by this implementation**. Sources: `src/decisions/spacing.ts:8-21`.
- With an active numeric scale, pure `var(--spacing)` or a simple multiplicative `calc(var(--spacing) * n)` in either order passes; arbitrary arithmetic mentioning `--spacing` does not automatically pass. Half steps describe nearest choices, not a restriction that every accepted multiplier must be a half step. Sources: `src/rules/provenance.ts:245-246`, `src/rules/provenance.ts:176-178`.
- This fixture's custom named spacing decisions replace the numeric scale; `gap-3` compiles to the explicitly authored `--spacing-3`, not an inferred universal promise that “3 always means 12px.” Sources: `fixtures/docs-judged/src/styles.css:3-12`, `src/decisions/spacing.ts:17-21`, `src/lower/tailwind.ts:212-223`, `scripts/docs/record-judged.mjs:50-57`.
- Negative spacing compares by magnitude to positive scale steps; class edit text preserves an authored negative sign. Generated choice CSS from `useFor()` does not itself negate the token. Do not present it as a guaranteed negative inline/CSS rewrite. Sources: `src/rules/provenance.ts:123-126`, `src/rules/provenance.ts:185-189`, `src/messages.ts:79-95`, `src/rules/provenance.ts:39-42`.
- Zero spacing/radius passes independently of a scale; spacing `auto`, inheritance/reset keywords, `normal`, and resolved percentages are exempt. `px` is a separate surprise: named class candidates such as `gap-px` are marked compiler-owned and skipped for provenance, whereas authored `gap: 1px`/`gap-[1px]` are judged. Sources: `src/rules/provenance.ts:241-255`, `src/lower/tailwind.ts:195-196`, `src/rules/families.ts:24-27`.
- The fixture's default Tailwind import contains `--spacing: 0.25rem`, but this is framework content read from the installed package, not a hardcoded Plumb ladder. Its resolved size would depend on the project's override and Plumb's 16px rem comparison assumption. Sources: `fixtures/docs-judged/src/styles.css:1`, `node_modules/tailwindcss/theme.css:325`, `src/lower/tailwind.ts:150`, `src/lower/tailwind.ts:184`, `src/decisions/resolve.ts:9-11`, `src/decisions/spacing.ts:11-21`.
- Additional fixture output includes `dead/spacing` (**info**) for unused decisions; choice recommendations do not establish actual source references. Dead decisions use reference reachability/export policy, not equality with literals. Sources: `src/rules/dead.ts:12-47`, `src/rules/dead.ts:49-68`, `scripts/docs/record-judged.mjs:90`.
- CLI exit code **1** here is expected because authored failures are intentional, not a recording failure. The recorder validates every selected declaration, resolution, rule/severity, choice order, authored line and the on-scale absence of findings before writing. Sources: `src/cli.ts:62`, `scripts/docs/record-judged.mjs:20-23`, `scripts/docs/record-judged.mjs:48-67`, `site/src/docs/recordings/judged.json:6`.
