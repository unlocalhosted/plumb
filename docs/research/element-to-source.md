The central distinction is **which source relationship is being returned**. A host's JSX creation site, a component's definition, the `<Button />` invocation in its caller, and the declaration that contributed a particular CSS class are different locations. An owner chain records creation relationships; Fiber `return` records reconciliation ancestry; DOM parents record rendered containment. These relationships diverge for wrappers, slots, render props, portals, and server components. A successful editor jump does not establish class provenance or authorize an edit.

Findings below distinguish implemented behavior from source-derived failure risks. “Not found” means absent from the inspected attribution path, not proof that no extension or future version can implement it. None of these source reads establishes an end-to-end compatibility or performance result.

## Vite ecosystem: `vite-plugin-react-inspector`

Identity: **sudongyuer/vite-plugin-react-inspector**, manifest **0.3.3**, commit [`1f4284ebae2ca7001aff5be4619cd53be49ed862`](https://github.com/sudongyuer/vite-plugin-react-inspector/tree/1f4284ebae2ca7001aff5be4619cd53be49ed862). This is a third-party Vite plugin, not Vite core's inspector.

1. **Mechanism / React 19.** A Vite `enforce: 'pre'`, `apply: 'serve'` transform parses `.tsx`/`.jsx` with Babel's env/react/typescript presets, traverses `JSXElement`, then uses MagicString to insert `data-react-inspector="absoluteModuleId:line:column"`. It skips JSX member expressions whose object is named `React`. Babel's column is inserted without adding one. Runtime reads the attribute directly; no Fiber, `_debugSource`, `_debugStack`, owner stack, or source-map lookup is used for the editor jump. Attribute mapping therefore does not depend on React 19 retaining `_debugSource`. [Transform and middleware, `src/index.ts` L7–88](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/index.ts#L7-L88).

2. **Library boundary.** The transform checks file extension and excludes only its own Toggle source. It does not implement `node_modules` exclusion, package-name ownership, project-root membership, or configurable include/exclude. Whether a dependency gets instrumentation depends on whether Vite sends its original JSX through this transform. Custom component invocations get attributes as props; the DOM receives them only if component implementation forwards them. Thus local shadcn source can be annotated, while compiled Radix/Base UI internals usually cannot. Linked/workspace JSX is treated like any other transformed module, with its module ID; no monorepo boundary policy exists. These are consequences of the same transform, not tested package-specific integrations. [Transform selection and injection L19–58](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/index.ts#L19-L58).

3. **Multiple levels.** A draggable toggle enables hover file/line/column text and click-to-editor. Both callbacks read `event.target.getAttribute('data-react-inspector')`; there is no nearest annotated parent lookup or owner/component chooser. A child SVG or unannotated nested element can therefore lose the surrounding component's location. [Toggle L8–33, L71–89](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/Toggle/Toggle.jsx#L8-L89).

4. **Computed classes.** No reverse mapping for `cva`, `tailwind-variants`, or `cn`. The transform marks JSX start positions, not class expressions; runtime only consumes that location. [Injection L34–47](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/index.ts#L34-L47).

5. **Hosts / cost / development.** Vite dev-server adapter, HTML script injection, and local editor middleware. No Next webpack/Turbopack or RSC-specific adapter in this implementation. MagicString generates a map with source content to preserve downstream transforms, but the inspector itself avoids map-fetch/decode cost. Babel parsing happens on transformed JSX files; there is no explicit attribution cache. `apply: 'serve'` provides the plugin's production gate. [Index L7–88](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/index.ts#L7-L88).

6. **Failure evidence.** Source-derived risks: component props dropped/overwritten; exact event target lacking annotation; zero-based columns passed to editor; hover display uses `file.split(':')`, despite editor middleware having a Windows-aware parser. The injected UI itself uses legacy `reactDOM.render` and temporarily suppresses `console.error`: React 19-independent location metadata should not be confused with proven React 19 UI compatibility. The package declares React/ReactDOM `^18.0.0`; if its UI resolves ReactDOM 19, removed `render` is a separate obstacle. [Toggle L8–20](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/Toggle/Toggle.jsx#L8-L20), [editor path parser L11–24](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/utils/index.ts#L11-L24), [UI bootstrap L14–21](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/src/inject.jsx#L14-L21), [manifest](https://github.com/sudongyuer/vite-plugin-react-inspector/blob/1f4284ebae2ca7001aff5be4619cd53be49ed862/packages/vite-plugin-react-inspector/package.json).

## `unplugin-dev-inspector`: identity and two distinct transforms

Its [manifest identifies that package and repository](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/package.json#L1-L16); its [core names the plugin `unplugin-dev-inspector`](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/core.ts#L9-L31). The exact unsuffixed npm registry lookup returned 404 during research. This report explicitly studies the matching MCP project rather than silently treating unrelated inspector packages as equivalent.

1. **Mechanism / React 19.** The common unplugin path uses Babel parser/traverse plus MagicString to inject `data-source="cwdRelativeFile:line:column"` into JSX opening elements, including custom components, member expressions, and generics. It skips Fragment/React.Fragment and existing attributes; columns remain Babel's zero-based columns. Its **Turbopack loader uses a different implementation**: `@code-inspector/core`'s `transformCode`, producing `data-insp-path`, absolute paths, and one-based columns. Runtime accepts both attributes. These paths survive removal of `_debugSource` because DOM metadata is primary. Fiber fallback discovers a function name and optional `window.__SOURCE_INSPECTOR__[name]`; it does not parse `_debugStack`, use `captureOwnerStack`, or resolve source maps. [JSX transform L20–153](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/compiler/jsx-transform.ts#L20-L153), [loader L24–70](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/loader.ts#L24-L70), [source detector L172–283](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/client/sourceDetector.ts#L172-L283).

   **Dependency version matters:** the lockfile pins `@code-inspector/core` **1.3.0**, not current 2.0.9. At its release commit `76c4bd1a449de4a82a15b82e9993080737b897c6`, that transformer inserts static `data-insp-path` and does not perform the newer component-root propagation. It obtains `node.openingElement.name.name`, so member-expression tags such as `<Dialog.Content>` are not annotated by that historical transformer. Do not transfer current code-inspector capabilities to this loader. [Lock L665–667](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/pnpm-lock.yaml#L665-L667), [core 1.3.0 transform L13–59](https://github.com/zh-lx/code-inspector/blob/76c4bd1a449de4a82a15b82e9993080737b897c6/packages/core/src/server/transform/transform-jsx.ts#L13-L59), [release manifest](https://github.com/zh-lx/code-inspector/blob/76c4bd1a449de4a82a15b82e9993080737b897c6/packages/core/package.json#L1-L4).

2. **Library boundary.** Common core skips any ID containing `node_modules`; there is no package-aware “nearest feature component” policy or source include/exclude option in `DevInspectorOptions`. JSX locations are relative to `process.cwd()`, not Vite's configured app root. Workspace files with real IDs outside `node_modules` can be transformed, potentially producing `../packages/...`; linked IDs retaining `node_modules` are skipped. Turbopack helper installs broad JS/TS glob rules, and its loader has no equivalent `node_modules` check. Local shadcn JSX is eligible; external Radix/Base UI need attribute forwarding or transformed dependency source. [Core L9–31](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/core.ts#L9-L31), [relative path L80–81](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/compiler/jsx-transform.ts#L80-L81), [options L19–150](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/utils/create-plugin.ts#L19-L150), [Turbopack rules L153–181](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/turbopack.ts#L153-L181).

Its Fiber fallback walks `_owner || return`, returns at the first named function, and can return `file: 'unknown', line: 0, column: 0`. This is automatic ancestor fallback, not an inspectable owner graph or “definition versus invocation” chooser. [Source detector L172–283](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/client/sourceDetector.ts#L172-L283).

Its own UI using `cva` does not constitute attribution support. [Element info L34–79](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/client/sourceDetector.ts#L34-L79), [JSX metadata transform L100–134](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/compiler/jsx-transform.ts#L100-L134).

5. **Hosts / cost / development.** Vite and webpack through unplugin, plus an explicit Turbopack rule helper/loader. Next uses a `"use client"` bootstrap that appends inspector UI and loads its script from a standalone server. Attribute injection can preserve locations in server-rendered host HTML if that server source is transformed; it does not reconstruct an RSC owner chain. No attribution map-fetch/decode cache is needed; Babel parses eligible files, MagicString generates downstream maps. Vite records command and suppresses transforms/HTML injection on builds; virtual modules become no-ops. For webpack/Turbopack, `enabled` defaults from `NODE_ENV` but **explicit `enabled: true` overrides that default**. The Next client bootstrap itself has no production check. Therefore dev-only installation/configuration is required; an unconditional production-zero-impact guarantee would overstate this code. [Plugin enable/transform L165–181, L275–305](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/utils/create-plugin.ts#L165-L305), [virtual module L319–325](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/utils/create-plugin.ts#L319-L325), [Vite build guard L405–417](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/utils/create-plugin.ts#L405-L417), [Next bootstrap L1–51](https://github.com/mcpc-tech/dev-inspector-mcp/blob/b168debce04e805c99fb40ca4cc4c4a32fc4e55f/packages/unplugin-dev-inspector/src/next.tsx#L1-L51).

## LocatorJS: legacy Fiber adapter and instrumented JSX adapter

Snapshot **ac4ed50a8f3668a3390488ea7af483fb97a58009**, runtime/Babel/webpack-loader manifests **0.5.1**. These are separate attribution mechanisms, with different chains.

1. **Mechanism / React 19.** Legacy React adapter asks DevTools renderers for `findFiberByHostInstance`, then reads `_debugSource` with `_debugOwner` fallback. No `_debugStack`, `captureOwnerStack`, or runtime source-map resolver replaces it. The Babel adapter instead inserts `data-locatorjs-id="absoluteFile::expressionIndex"` and per-file `window.__LOCATOR_DATA__` with expression name/location/enclosing function. Optional path mode emits self-contained `data-locatorjs="absoluteFile:line:zeroBasedColumn"`. The webpack/Turbopack loader forces path mode; runtime can recover a location without browser globals and adds one to the column. **That adapter**, rather than the legacy Fiber adapter, bypasses React 19's removal. [Fiber lookup](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/react/findFiberByHtmlElement.ts#L4-L26), [debug-source walk](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/react/findDebugSource.ts#L3-L14), [Babel metadata/injection](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/babel-jsx/src/index.ts#L207-L329), [loader](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/webpack-loader/src/index.ts#L67-L100), [self-contained path fallback](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/jsx/getExpressionData.ts#L8-L43), [column conversion](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/jsx/jsxAdapter.ts#L96-L127).

2. **Library boundary.** Babel hard-skips filenames containing `node_modules`. Loader also skips `middleware.`. `ignoreComponentNames` excludes exact tag names; built-ins exclude Fragment, Suspense, and names ending Provider. None is a package/workspace ownership authority or “skip to nearest feature owner” rule. **Inferred consequences:** local shadcn is eligible; installed Radix/Base UI is excluded; workspace JSX is eligible if its resolved filename lacks `node_modules` and its host compiler processes it. Custom-component call annotations require prop forwarding to reach DOM; an annotated internal host may identify implementation instead. Unmarked children use closest annotated DOM ancestor. [filename/name selection](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/babel-jsx/src/index.ts#L90-L118), [special names](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/babel-jsx/src/isDisallowedComponent.ts#L1-L10), [loader skips](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/webpack-loader/src/index.ts#L59-L63), [closest marker](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/jsx/jsxAdapter.ts#L20-L54).

3. **Multiple levels.** React adapter builds `_debugOwner` paths. JSX adapter walks `parentElement`, deduplicates component labels, and can expose an enclosing function definition recorded by Babel. That metadata records **FunctionDeclaration only**, with arrow/class support still TODO; self-contained path fallback has `wrappingComponentId: null`. ### Why `captureOwnerStack()` cannot replace clicked-node lookup

The public API takes **no element or Fiber**. It reads current React execution context, works in render/effects/React event/error callbacks, and can return null from a native document listener, timeout, or after async work. It is a development export; mixed bundles should guard namespace access. Browser console symbolication does not mean the returned string already carries original-source coordinates. Plumb's overlay event handler therefore cannot call this API and obtain an arbitrary target's owners. Retained `_debugStack`/owner metadata or build instrumentation is needed for that use case. [Official API contract](https://react.dev/reference/react/captureOwnerStack), [implementation](https://github.com/facebook/react/blob/b618bbb4422693bbb8d387180687b3f510300f42/packages/react/src/ReactOwnerStack.js#L12-L22).

## Cross-tool conclusions: boundaries and computed classes

**Path exclusion is not a design-system boundary.** Radix/Base UI installed as dependencies are mostly handled as excluded or package source. shadcn's copied local source is normally treated as user source; react-grab additionally downranks conventional shared-UI paths. Workspace/symlink behavior depends on path spelling and compiler coverage in most tools. Only code-inspector among the examined attribute inspectors offers explicit include precedence plus documented linked-package mappings; neither that nor react-grab's package-name heuristics proves a mapped target is safe to edit.

**No reviewed competitor provides general rendered-class provenance through `cva`, `tailwind-variants`, or `cn`.** Their evidence returns element/component/stack locations or current class values. Locator's styled-template instrumentation and DevTools' StyleX inspection are narrower features. One JSX location cannot distinguish a base variant token from a caller override, a class merged out by twMerge, a class contributed by a library, or a dynamically constructed value. Exact class provenance needs separate expression/dataflow evidence; runtime observation and candidate static sites should remain separately labeled.

That is useful static provenance, but does not prove which variant branch or merge survivor contributed one clicked element's class during this render. Keep that distinction when interpreting owner-callsite fallback, which may expose caller overrides while library/shared-component base styles originate elsewhere. ## Ranked ideas for Plumb

1. **Expose typed source candidates, then an owner chooser.** Preserve distinct entries for clicked host JSX, component invocation, component-body/definition, render parent, and injected-HTML host. Keep current precise default; let users choose component implementation versus feature usage without silently replacing one with the other. Show filename, relationship, and acceptance/refusal reason. Evidence: bippy changes location semantics across fallbacks; DevTools separates component source from creation stack; react-dev-inspector exposes source/render tabs. [bippy precedence](https://github.com/aidenybai/bippy/blob/2c148fc34ca5f3142c65646e94eea785aff73791/packages/bippy/src/source/get-source.ts#L93-L156), [DevTools source extraction](https://github.com/facebook/react/blob/b618bbb4422693bbb8d387180687b3f510300f42/packages/react-devtools-shared/src/backend/fiber/renderer.js#L7972-L8035), [chain panel](https://github.com/zthxxx/react-dev-inspector/blob/3292e226597e1bafc11bbeefeded416b02c05c58/packages/web-components/src/InspectContextPanel/ElementInspectPanel.tsx#L124-L170). Implement evidence schema first, then one chooser component; never turn inferred definition evidence into an exact editable JSX site.

2. **Add optional dev-only, self-contained JSX instrumentation for missing metadata and RSC host output.** Existing `data-plumb-source` acceptance is a useful seam. Instrument original positions before JSX lowering, carry explicit line/column convention, generate correct maps, guard transform and runtime separately, and preserve server tracked-file/hash/anchor validation. Mark custom-component invocation separately from host implementation; avoid replacing both with one forwarded prop. Evidence: Locator path mode works without browser-side metadata; code-inspector's root rewriting establishes invocation propagation but discards separate location and changes component parameters. Do not copy its map passthrough or hydration-warning suppression. [Locator loader](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/webpack-loader/src/index.ts#L67-L100), [path fallback](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/jsx/getExpressionData.ts#L8-L43), [root precedence](https://github.com/zh-lx/code-inspector/blob/6235e8a97a484237b7308e13d7d700e5e7f3fea4/packages/core/src/server/transform/transform-jsx.ts#L839-L867), [Plumb explicit seam](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/overlay/src/locate.js#L168-L173).

3. **Separate shared-UI ranking from edit authority.** Add configurable feature/implementation preference among already validated project sources. Use package/workspace declarations or explicit paths as authority; use familiar shadcn/`components/ui`/`packages/ui` conventions only as overridable ranking hints. Retain shared UI as selectable implementation because Plumb users may intentionally edit design tokens there. Evidence: react-grab's shared-UI precedence improves feature context while keeping fallback; its package-name heuristics can misclassify relative workspace sources. Plumb's stronger tracked/realpath boundary must remain decisive. [Shared UI rules](https://github.com/aidenybai/react-grab/blob/ea4bbec9e80f4802e8ae19ad18431edb9ddbb670/packages/react-grab/src/constants.ts#L22-L35), [selection precedence](https://github.com/aidenybai/react-grab/blob/ea4bbec9e80f4802e8ae19ad18431edb9ddbb670/packages/react-grab/src/core/context.ts#L339-L382), [Plumb acceptance boundary](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/src/session/index.ts#L328-L359).

4. **Make workspace/root behavior explicit before adding path mappings.** Explain which repo/package root owns editable sources and why a linked package was refused. Prefer tracked real source under configured monorepo root. If later supporting external workspaces, require separately registered canonical roots, source snapshots, and original-coordinate evidence; an existing file at a remapped path is insufficient. Evidence: code-inspector documents include+mappings for linked packages but does not map original line coordinates; Plumb already resolves served root separately and rejects symlink aliases. [Linked packages](https://github.com/zh-lx/code-inspector/blob/6235e8a97a484237b7308e13d7d700e5e7f3fea4/docs/en/api/advance.md#L61-L117), [Plumb root choice](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/src/hosts/vite.ts#L29-L60), [canonical-path check](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/src/session/index.ts#L338-L349).

5. **Bound cold attribution work while preserving current lazy caches and freshness checks.** Add measured fetch concurrency/size/deadline budgets where absent; reuse in-flight work, cancel stale selection, and keep transient failures retryable. Do not eagerly symbolicate every Fiber merely to filter libraries. Plumb already has worker fallback, lazy row/section decoding, shared requests, and generation/hash checks; preserve those and measure a cold Next chunk plus a hover burst before tuning. Evidence: react-grab's documented three-fetch/eight-second budget targets actual saturation; bippy exposes bundle/map size bounds; DevTools disables location filtering because eager mapping costs too much. [Grab limits](https://github.com/aidenybai/react-grab/blob/ea4bbec9e80f4802e8ae19ad18431edb9ddbb670/packages/react-grab/src/constants.ts#L36-L68), [bippy map bounds](https://github.com/aidenybai/bippy/blob/2c148fc34ca5f3142c65646e94eea785aff73791/packages/bippy/src/source/symbolication.ts#L80-L95), [disabled eager filter](https://github.com/facebook/react/blob/b618bbb4422693bbb8d387180687b3f510300f42/packages/react-devtools-shared/src/backend/fiber/renderer.js#L1147-L1161).

6. **Treat Flight-owner traversal and Next server symbolication as a separate capability.** Extend owner records to model Fiber and Flight owners only when source provenance and boundary rules can be verified. An opt-in Next frame endpoint adapter can enrich server locations; return explicit unsupported/timeout/raw-frame evidence rather than a guessed file. Ensure click, label, owner menu, and editor action use the same resolver capability. Evidence: bippy understands `.owner`/`.debugStack`; react-grab has a version-gated Next server-frame route; Locator's JSX-first click/React-first parent defaults show how separate flows drift. [Flight owner walk](https://github.com/aidenybai/bippy/blob/2c148fc34ca5f3142c65646e94eea785aff73791/packages/bippy/src/source/owner-stack.ts#L535-L568), [Next symbolication adapter](https://github.com/aidenybai/react-grab/blob/ea4bbec9e80f4802e8ae19ad18431edb9ddbb670/packages/react-grab/src/core/next-server-frames.ts#L67-L149), [Locator parent priority](https://github.com/infi-pc/locatorjs/blob/ac4ed50a8f3668a3390488ea7af483fb97a58009/packages/runtime/src/adapters/getParentsPath.tsx#L38-L45). Public `captureOwnerStack()` is not the target-node API for this work.

7. **Build class provenance as a distinct layer over the static collector.** Start with one supported helper/feature slice: retain class literal definition, invocation, conditional branch, and rendered-token observation as separate records. Report candidate contributors when active branch or merge order is unproved; refuse an automatic edit when multiple sites remain plausible. Existing `cva`/`tv`/`cn` collection gives Plumb a better starting point than these element inspectors, but no competitor supplies a general runtime reverse mapper to adopt. Evidence: [Plumb helper/config analysis](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/src/collect/classes.ts#L278-L315), [JSX context](https://github.com/unlocalhosted/plumb/blob/19d781142372d419ba8d3d1ec64098cf6d172f2e/src/collect/classes.ts#L390-L403), [Grab reads rendered class only](https://github.com/aidenybai/react-grab/blob/ea4bbec9e80f4802e8ae19ad18431edb9ddbb670/packages/react-grab/src/core/html-preview.ts#L27-L38).
