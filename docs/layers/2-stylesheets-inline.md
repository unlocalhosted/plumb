# Layer 2: stylesheet and inline lowering

Built Layer 2 only. Stylesheets and inline styles now feed the same `Declaration` type as classes and arbitrary utilities. Existence remains the only judgement: no decision extraction, provenance, habits, ownership, ledger or baseline rules were added. No packages were installed, no commits were made, and MetalUI was read-only.

## Built

- `src/collect/modules.ts` follows runtime static imports, export-from edges and string-literal dynamic imports transitively from scanned source files, including workspace packages and node_modules. Oxc resolution honors each importer's tsconfig paths, package exports, import/browser/default conditions, browser/module/main fields and JS-to-TS extension aliases. Type-only edges, declaration files, JSON and assets do not enlarge the module graph. Canonical resolver paths map back to scanned source paths, preventing duplicate modules/stylesheets through symlinks. Cycles terminate. Work is capped at 20,000 external modules, 64 MiB total external source and 4 MiB per module; hitting a cap produces explicit incomplete-proof notes.
- Scanned files share their existing parse's Oxc module record. External modules use `parseSync(...).module` without reading `.program`: native syntax parsing still reads the module, but JS only materializes import/export records, never its full AST or class/inline sites. Escaped dynamic string literals are decoded by Oxc; comments, quoted examples, regexes and nonliteral dynamic imports cannot invent edges. Parsed records and resolved edges are cached by file mtime/size under the existing cache directory. Warm hits skip reading/parsing external module source; edges are revalidated with a fresh resolver every run so independent tsconfig/package-export edits and symlink changes cannot leave stale reachability.
- `src/collect/stylesheets.ts` follows the entry's imports/references, CSS imports from every reached module, and source-glob CSS. Package roots that resolve to CSS are supported too. CSS-specific resolution matches Tailwind's loader: `.css`, the `style` main field/export condition, node_modules and NODE_PATH. Relative imports resolve from the importing file. Every file records its entry/import/reference/side-effect/module/source reaches, including importer and specifier. `module` means an importer outside source globs; scanned importers retain `side-effect`. Explicit unresolved CSS imports fail with an actionable error. Remote stylesheets are not fetched and produce a note.
- Source parsing is shared with Layer 1. `src/collect/inline.ts` reads inline objects, imports and static JSX `<style>` content before the existing class walk releases each AST. Traversal includes elements inside JSX-valued props and object slot payloads. Static strings/templates preserve a cooked-character-to-source-offset map, including escaped newlines and Unicode escapes. JSX CSS declarations point to the JSX source, and its selectors register classes. The benchmark's `naive-cap` marker was removed; Button.tsx:351 now supplies its real existence proof.
- `src/lower/stylesheets.ts` uses the project's Tailwind compiler for feature-bearing CSS (`@apply`, `@utility`, `@custom-variant`, `@variant`, `@theme`, `theme()`, `--theme()`, `@reference`, config/plugins). It prefers the project Node wrapper only when it resolves the same Tailwind installation. Independent feature files reference the entry's theme/utilities without emitting the entry again. The real `compile(...).build([])` API lowers stylesheet paint without inventing class usage or duplicating candidate-generated utility rules. Its decoded source map preserves original file/property positions; generated apply declarations point at the authored `@apply`, rather than utility definitions or generated CSS lines.
- Plain CSS uses Lightning CSS's validated rule AST, with nesting resolved during traversal. Each comma selector gets its own declaration context, so an adjacent plain selector does not inherit a sibling's hover. Pseudos are parsed from the complete resolved selector. Media, supports, container and layer conditions survive both nesting and CSS imports. A file reached through a scoped CSS import and an independent JS import keeps both contexts; source-glob discovery alone does not add an unconditioned copy of an already imported file.
- Raw declaration recovery keeps authored/plain values, compiled Tailwind values, exact property locations, duplicate declarations, custom token blocks and optional final semicolons. Keyframe bodies have `origin: 'keyframes'`, including custom properties within frames. Other stylesheet custom-property assignments have `origin: 'custom-property'`; apply paint has `origin: 'apply'`. Property registrations are compiler infrastructure, not element declarations. Tailwind may remove unused theme definitions from emitted CSS; their authored definitions remain in the graph for Layer 3's decision reader.
- Inline style values are read symbolically (`src/collect/evaluate.ts`). Literal strings, static templates and signed numbers lower directly. Lexical `const` bindings are followed through any number of hops, locally or through directly exported constants in imported modules (with that module's own constants in scope); object and array members, computed literal keys, `+ - * / % **` on numbers, string concatenation and `Math` calls on numbers fold. A value with finitely many outcomes becomes one declaration per outcome under a `branch` condition: ternaries, `||`/`??`/`&&`, a table read by a runtime key (every row, `key === "name"`), and a parameter typed with a literal union (`size: 'sm' | 'lg'`, through an inline type, a local alias or interface, or `FC<Props>` on the variable), which also expands a hole inside a variable name (`` `var(--spacing-${size})` ``) into names that are each checked. A template hole that cannot be decided is tolerated when every top-level part that contains a hole also references a variable, and never inside a variable's name: the declaration keeps the authored `${…}` text, `dynamic: { kind: 'reference', by }`, and is judged by reference. A constant times a runtime number is a step: `value` is the step with React's px rule or the template's unit, `dynamic: { kind: 'step', by }`, and provenance judges the step with its own title; its edit writes `` `calc(var(--token) * ${by})` ``. Spreads of readable objects bring their properties, nested up to four levels; `cond ? a : b` between whole objects reads both. The site is the consuming style attribute for values reached through a binding, and the property itself for direct literals; the owner is its element/component. Type assertions are unwrapped. Camel case becomes kebab case; numbers follow React's exact unitless list, including its explicit vendor spellings, and zero/custom-property numbers have no px suffix. The list is copied from [React's MIT-licensed source](https://github.com/facebook/react/blob/main/packages/react-dom-bindings/src/shared/isUnitlessNumber.js), also verified against the installed React DOM implementation. Only what source cannot decide stays opaque: an untyped parameter, a call, a hole with no token beside it. Those retain their known property with `value: 'dynamic-value'` and `opaque: 'dynamic-value'`. Unreadable spreads, unknown keys and unreadable objects use `prop: '*'`, `opaque: 'spread'`. Custom-property assignments retain their custom-property origin even when opaque. Function parameters shadow constants; `let` bindings are unknown.
- `Declaration.origin` identifies syntax; optional `sourceOrigin` identifies project/framework provenance. CSS reached only through external modules supplies selector existence proof and carries `sourceOrigin: 'framework'` and its nearest package name, including workspace packages. Declarations remain available for inspection without becoming project sites for future rules. A workspace stylesheet independently reached by entry/CSS imports or explicit source globs remains project-authored; node_modules CSS retains framework provenance. Class bracket-value/property uses have arbitrary origin. References exclude CSS strings/comments; no value resolution or family shorthand expansion was added.
- Reports expose all declarations, stylesheet reach records and package names, counts by declaration origin/reach kind, literal inline-site counts, opaque declaration/spread counts, and stylesheets/inline timing phases. `moduleGraph` additionally records total runtime modules, external modules followed, CSS files reached through those modules (including CSS descendants), external parse-cache hits/misses, native import-record parsing time and total graph time. Graph time is included in the stylesheets phase. Reach counts overlap when a file has several reach kinds. Declaration counts include selector contexts and independent import contexts; they are not counts of physical lines. The report schema and text output cover these fields. `explain` retains Layer 1's class sites and additionally exposes the unified declaration array; CSS files and TSX inline/embedded CSS both work, with origins and conditions in text and JSON.
- Stylesheet lowering is cached by file contents, reaches, provenance, entry/version, feature-root import/config/plugin hashes and complete embedded JSX source/offsets. Warm hits skip compiler loading and CSS parsing. Graph collection and inline extraction still run. Class cache format advanced to preserve layer conditions. `PLUMB_CACHE_DIR` redirects candidate, stylesheet and module caches for read-only benchmarks.

## Scope limits

No cascade, variable/calc resolution, family expansion, boolean media-query judgement, decision extraction or habit findings. Conditions retain query/pseudo text for later rules. Runtime JSX stylesheets, CSS-in-JS, CommonJS require calls, nonliteral dynamic module imports, re-export chains for inline constants, mutable/computed style containers and multi-hop evaluation remain unreadable. The module graph adds CSS existence proof without scanning external JSX/inline declarations or performing bundler tree-shaking. Direct plugin/config dependencies are hashed, but their transitive JS dependency graph remains Layer 1's documented compiler-cache limitation. Source-map compilation is verified against Tailwind 4.3.3; older compiler API compatibility is not separately proven.
