# Layer 1: class lowering and existence

Built only class collection, Tailwind candidate lowering, existence judgement, reporting and `explain`. No provenance, stylesheet/inline declaration lowering, ownership, habits, ledger or baseline logic runs. No packages were installed and no commits were made. Existing package.json/package-lock.json changes were preserved.

## Built

- `src/collect/classes.ts` prefetches JS/JSX/TS/TSX source texts and parses with oxc-parser, using `experimentalRawTransfer` when `rawTransferSupported()` is true and JSON transfer otherwise. Line-offset tables avoid repeatedly splitting whole source prefixes; direct visitor-key traversal skips type-only edges and leaves. Functions with no class/helper spelling are skipped, conservatively retaining any function containing backslashes. Completed ASTs are released after exported literal nodes are retained. It records class/className attributes, helper arguments, clsx object keys, arrays, conditional/logical branches, cva/tv bases, variants, compound classes and slots. Helpers include cn, clsx, cx, classNames, twMerge, twJoin, cva, tv and configured `classHelpers`. Recognized helpers nested in an otherwise unreadable call are still collected.
- Lexical const bindings are followed one hop. Literal strings, literal object maps and literal arrays resolve locally or through imports resolved with oxc-resolver and automatic tsconfig paths. Dynamic map indexes enumerate all literal values; static keys select their value. Both definition and reference locations are recorded. Source imports may resolve outside the source globs, including package modules. Import resolution is lazy: only imports read as class values need their literal exports, so unrelated component/library ASTs are not materialised. Imported component bodies are never scanned as additional source files.
- Each site has one-based line/column, token, element/component/function owner and branch conditions. Unknown expressions increment the opaque count without producing dead-class findings. Template holes are counted; static tokens survive. A static fragment glued to an unknown hole produces existence/dynamic-class. Readable conditional holes that supply whitespace boundaries are collected without false fragment findings.
- `src/lower/tailwind.ts` resolves Tailwind from the CSS entry directory. It prefers the project's @tailwindcss/node loader only when that wrapper resolves the same Tailwind installation; otherwise it loads that Tailwind directly with stylesheet and module file loaders. A CLI integration test supplies a distinct project compiler to prove there is no fallback to Plumb's installed compiler.
- One candidatesToCss call compiles all cache misses. Lightning CSS parses the returned CSS; nesting produces resolved selector, pseudo, media, supports and container conditions. Values stay as emitted by Tailwind. Local --tw-* assignments are folded when all reads can be substituted within that rule; ambiguous/cross-rule cases retain raw declarations and a note. @property registrations and keyframes are compiler infrastructure, not element declarations.
- Candidate CSS, lowered declarations and notes are cached under root/node_modules/.cache/plumb, or root/.plumb-cache without node_modules. The candidate key includes a hash of the entry stylesheet import/reference graph, directly referenced config/plugin contents, Tailwind version, Plumb version and a cache-format revision. Fully warm runs with the same candidate set skip compiler loading and compilation. Hint indexes are separately keyed by candidate set; changing the source slice can refresh hints without recompiling cached candidates. `PLUMB_CACHE_DIR` redirects the cache for read-only benchmark roots.
- `src/rules/existence.ts` registers class selectors from every .css file under the root, excluding node_modules/dist/build/.next/.git. It uses Lightning CSS selectors, including escaped names and selectors inside :is/:not. This is deliberately broader than the import graph until Layer 2. Recoverable CSS warnings appear in report notes; expected Tailwind preprocessing directives do not become noisy unknown-rule notes.
- Classes with neither compiler output nor a registered selector are existence/dead-class errors. Built-in group/peer markers, named group/peer markers and configured `markers` globs pass. Markers and classHelpers are non-empty-string arrays in the typed config schema and runtime validation; marker matching uses Node's glob matcher.
- Findings group by rule and class token, deduplicating physical locations. Fixes suggest at most two names sharing a utility prefix or having normalised edit distance <= 0.34 of the longer base name. Utility variants survive replacements. Same-prefix candidates rank first; authored theme keys/utilities rank ahead of compiled candidates, with exact suffix/shared-leading-spelling tie-breaks. When nothing qualifies, no suggestion is printed. Theme hints come from authored @utility names and compiler completions matching non-default theme keys; the large getClassList expansion is not used. Single-segment custom namespaces do not imply utility-value families, and ambiguous static/functional roots need functional usage proof before value hints are indexed.
- Reports populate findings and coverage.existence `{ total, dead }`: static collected sites and dead physical sites respectively. `classes.unique` counts compilation candidates; `classes.opaque` counts unreadable expressions/holes. Timing records discover/parse/collect/load/compile and cacheHits/cacheMisses. Text locations are relative to the root and findings list all grouped sites. Internal notes appear only with `--verbose`; JSON always retains `notes` arrays. Error findings exit 1 on every check, including the first run.
- `plumb explain <file>` and `--json` expose every collected site in that file, declarations, owners, conditions and lowering notes. Explain exits 0 because it is an inspection command, even when the project has findings. JSON report schema and README were updated.

## Verification

`fixtures/classes` exercises a typo, independent plain CSS, escaped and nested selectors, built-in/configured markers, configured helpers, imported literal maps via tsconfig paths, local strings/maps, arrays, clsx object keys, cva/tv variants/slots/compound classes, both conditional branches, logical branches, JSX class, helper calls outside JSX and inside unreadable wrappers, dynamic fragments and safe template boundaries.

The real compiled CLI e2e checks JSON findings, exact definition/reference locations, owners and branch text; explain verifies hover/media/supports/container/descendant conditions. Suggestion fixtures verify close matches, distant-name suppression, never-collected theme-key preference, variant retention, lamp-live selection when available and cache reuse after a candidate-subset change. Collector e2e verifies earlier-file exports after AST release and escaped helper calls after function pruning. It also checks default/verbose check and explain output, unchanged JSON notes, same-rule variable folding, conservative shadow lowering notes, rounded-full's infinity value, quoted CSS punctuation and keyframe exclusion. A repeated run proves cache hits and zero compilation; editing an imported stylesheet invalidates the cache. Separate CLI integration uses synthetic project packages to verify direct file loaders, project compiler identity, Node-wrapper preference and one unique-candidate compile batch. Config validation cases exercise both new keys. Tests are exclusively CLI integration/e2e, with no unit tests.

Final checks: `npm test` passes all 45 CLI integration/e2e tests (zero skips), and `npm run typecheck` passes. `git diff --check` is clean. Existing harness e2e remains green; its expected coverage and obsolete layer-0 text assertion were updated.

## Limits and open questions

- Import resolution is one hop to directly exported literal constants, including export aliases. Barrel/re-export chains, namespace access, mutable bindings, maps whose values are identifiers, and computed object keys remain opaque. Helper names must match the built-ins or config; renamed helper imports can be added through classHelpers.
- Template holes remain opaque even when selected string branches can establish safe token boundaries. General runtime string evaluation is not attempted.
- A CSS-declared class has existence proof but no lowered declarations from that stylesheet yet. Inline JSX `<style>` strings are outside this layer's registry; the benchmark's exact naive-cap exemption documents that case. Layer 2 will narrow the root-wide registry to reachable stylesheets and lower stylesheet/inline declarations.
- Class declarations keep emitted shorthand properties. Family-aware expansion, theme value resolution, provenance and arbitrary-value judgement remain later layers.
- Same-rule --tw-* folding is intentionally conservative: unresolved reads, fallbacks with nested functions and cross-rule dependencies are kept raw. Later declaration judgement must account for those notes rather than pretending they were folded.
- CSS graph and directly referenced config/plugin files are hashed; transitive JS dependencies of a plugin/config are not traced yet. That dependency graph is an open cache-invalidation question for plugin-heavy projects. Cached CSS is project-wide; a per-file AST/content cache is not built in this slice.
- `explain` scans the configured project to attach imported-map sites; its opaque count is project-wide. A file with no collected sites prints an empty site list. It is not a watcher or a change-scoped command.
- Raw transfer is an experimental Oxc runtime option omitted from the installed README and TypeScript options type; upgrades must recheck its API and platform support. Unsupported platforms use the slower JSON-transfer path. Benchmark timings are individual local measurements, not cross-platform guarantees. The authored theme-hint index is cached; lazy provenance/value indexing remains a later-layer concern.
