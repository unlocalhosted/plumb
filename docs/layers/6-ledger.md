# Layer 6: ledger

Built the ledger slice only, over the existing collectors, decisions and rules. No packages installed, no worktree commits, no MetalUI writes. `src/report.ts` changes are types/schema fields only; `formatText`, `formatFinding` and `brief` are untouched. Project-specific benchmark mapping remains under `bench/metalui/`.

## Identity and storage

`.plumb/ledger.jsonl` contains one JSON object per line, sorted by key. Writes validate the complete replacement then rename a temporary file. Duplicate keys, malformed JSON, invalid kinds/counts and invalid known field types produce actionable usage errors. The entry schema is `schema/ledger.schema.json`.

Ledger site keys are `rule:owner:prop:authored@path#anchor`. Authored forms strip quotes and collapse whitespace; they do not use resolved values or line numbers. Resolution is stored as data. Identical physical sites in one anchor share an entry with a positive count. Compiler fallback/condition copies do not inflate that count. These identities are separate from report finding keys: provenance findings stay grouped by fix (rule, family, amount), regardless of ledger presence or acceptance. For example, `margin: 10px`, inline `padding: 10`, and `gap-10` share a 10px spacing finding but have distinct ledger keys. Grouped provenance and existence findings carry optional exact `occurrences`, so a group containing different properties, syntaxes or owners does not excuse the wrong site. Future rules can supply occurrences; otherwise the ledger maps their sites back to declarations and falls back to their representative declaration. There is no rule-name allowlist or inline suppression syntax.

The shared source-site builder finds the nearest named function/component, including nested declarations, variable-bound arrows, callback wrappers and methods. Module-level sites use `<module>`. Definition and consuming sites retain their own source anchors. CSS collectors expose resolved selector anchors, including nesting and JSX styles. Compiled CSS locations recover the authored declaration text before key construction. The stylesheet cache revision changes to include anchors. Absolute filename owners for selectorless declarations normalize to `<module>`.

## Commands

- `baseline` records all current rule findings as debt, including warnings, and snapshots current decisions as inferred on first adoption. Existing exceptions survive. Existing debt may shrink; new keys or larger counts refuse with a message naming `--force`. A completed empty baseline also refuses later growth.
- `init` writes an inferred config naming discovered CSS decision sources, snapshots current decisions with `inferred: true`, and asks for baseline. It refuses to overwrite a config. `.plumb/.baseline-pending` distinguishes the initial init/baseline flow from debt growth after a completed baseline; the first successful baseline removes it. Usage-ladder inference, habit discovery and component-decision extraction are outside this layer.
- `accept <key> --why "…"` and `accept --rule <rule> --site <file:line> --why "…"` record bounded exceptions. Missing/blank reasons refuse. A rule/site can select several properties at that source line. Reasons, date and available Git author are recorded; author lookup happens once per operation, not per entry.
- `accept-decisions [--why "…"]` accepts current decision snapshots. Without a supplied reason it retains source reasons; unchanged entries retain their attribution. Decision reasons are optional, unlike exception reasons.
- `ledger --ratchet` shrinks debt counts and drops fixed debt. `--prune` removes wholly stale debt/exceptions and vanished decisions. Flags can be combined.
- `ledger --rebase` moves only orphaned entries whose old file/anchor vanished. Matches preserve rule, owner, property, authored text, resolved data and count, preferring a retained anchor for file moves or a retained path for anchor moves. Ambiguous matches remain failures. Fixed sites in a retained function cannot transfer their allowance to an unrelated function. Every move is printed and available in JSON.
- `show <key|rule>` lists all current sites and saved ledger lines, including stale entries. `why <file>:<line>` exposes lowered declarations, current rules, matching/nearest decisions and accepted ledger lines with reasons and locations. Accepted literal ladder values can name their decision too.

## Check behavior and Git

Each finding site carries optional `ledger: { key, status, why? }` data, with status `new`, `debt` or `exception`. The saved reason is included on covered sites when present. Count overflow remains new even when the authored key already exists. Report finding keys, sites, representative declarations, occurrences and fix grouping remain intact before and after baseline. A finding's overall status is `new` if any site is new, otherwise `debt` if any site is debt, otherwise `exception`. Mixed groups therefore expose every site's acceptance without splitting the fix. Only groups containing a new site in scope retain their original severity; fully covered groups become informational. Exit failure depends on new error sites in scope, not the number of findings or the status of a representative site. Ledger summaries and family debt/exception coverage count sites, including covered sites inside mixed groups.

First-run sites also expose authored ledger keys with `new` status. Pass `site.ledger.key` to `accept` or `show`; a finding's `ledgerKeys` lists all its authored identities for convenience, while its `key` remains the rule's fix-group identity. JSON includes classification, stable ledger keys, optional exact occurrences and a ledger summary. The CLI appends the ledger summary without editing the text formatter. Without a ledger, the original grouping and error-only exit behavior remain; both text and JSON summaries say to run `plumb baseline`.

Stale debt is `ledger/stale` (warn). Any exception without a nonblank why is `ledger/no-why` (error), including stale handwritten lines. New or changed decision snapshots are `decisions/unaccepted` (error whenever a ledger exists); removed accepted names are `decisions/vanished` (warn). Framework defaults are not implicitly accepted. A separate additive `decisionInventory` includes project theme keys outside configured judging ladders, so adding `--spacing-13` cannot bypass review simply because a preset excludes it. The spacing multiplier remains a unit, not a decision. Value/reference/origin/tier changes require acceptance; derived resolved values are data rather than site identity.

`check --base <ref>` compares source files against the ref, including uncommitted edits and untracked files. It judges sites in changed files against the full decision record and ledger. Unchanged-file sites stay in their fix groups and retain their ledger status; uncovered sites outside scope count in `ledger.outOfScope` rather than `ledger.new` and cannot cause exit failure. Groups with no new sites in changed files remain informational. Each added/changed exception or decision ledger line is reported as informational `ledger/grew`; new debt keys or larger debt counts are errors. Debt shrinkage is allowed. Comparison supports projects nested inside Git repositories and validates refs without passing user refs as Git options.

`check --strict-ledger` compares ledger/config growth against HEAD. Added exception/decision lines, new debt keys, increased debt counts and added config lines fail as `ledger/grew`. Config comparison covers supported config filenames plus an explicit config, includes same-length replacements and duplicate additions, and ignores blank lines/indentation. Debt count reductions remain green. `--base` and strict mode can be combined; their comparison diagnostics stay explicit. Check exits 0 with no new error findings, 1 with errors; malformed invocation/config/ledger/Git-ref errors retain the existing exit 2 contract.

Mixed debt/exception coverage and saved reasons are also asserted. Tests create commits only inside disposable Git fixtures for ref comparison; the Plumb worktree is not committed.

It runs baseline/check, adds precisely one gap-10, writes an exception without why, adds a spacing decision outside the preset ladder, and renames a copied docs file before rebase. ## Deliberate boundaries

The ledger does not evaluate rules, infer visual correctness, implement approvals/CI surfaces, or add habits/ownership. Git approver review is a later CI surface. Rebase refuses ambiguity instead of guessing. Minimal handwritten entries can suppress matching keys, but automatic rebase needs the metadata written by the CLI. Snapshot reasons are review evidence, not a security boundary. Ledger acceptance is site data; it never changes report grouping.
