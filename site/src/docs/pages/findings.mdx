Every finding Plumber prints has the same five parts, in the same order, so you can read one at a glance and act on it without opening the docs.

## Severity

| Severity | Means | Fails `plumber check` |
| --- | --- | --- |
| `error` | drift, or a style that can't work | yes, exit 1 |
| `warn` | worth a look, such as a literal that equals a token | no |
| `info` | a note, such as a value Plumber couldn't read | no |

The first time you run `plumber check`, with no config and no ledger, it reports everything and exits 0, so it's safe to try on any project. Once you've adopted Plumber, errors fail the check. A problem with the command itself, such as a bad flag, exits 2.

## One finding, many sites

The same drift in several places is one finding: the same rule, family and amount, with every site listed. The terminal shows the first five sites and says how many more there are; `--json` lists them all.

Plumber also keeps quiet about what you've already recorded. Findings fully covered by the [ledger](/docs/the-ledger) show as a single summary line. Add `--verbose` to see them, with each finding's rule id.

## Status

Every site carries a status from the ledger:

- **new**: not in the ledger. These are what fail a check.
- **debt**: drift you already had when you adopted Plumber, recorded so it doesn't block you.
- **exception**: accepted on purpose, with the reason someone gave.

A finding is new if any of its sites is new.

## In JSON

`plumber check --json` prints the same findings as data. Each has its `rule`, `family` and `severity`; the parts above as `title`, `because`, `choices` and `accept`; every site in `sites`, with its status; and `edits`, the exact replacements Plumber would make, which the overlay and agents use. The [report format](/docs/report-format) lists every field.
